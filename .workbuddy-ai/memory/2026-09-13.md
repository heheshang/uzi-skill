## three.js boot-intro (入场动画)

Rewrote the boot overlay's entrance as a three.js scene: two particle clouds (bull=green / bear=red)
fly in from ±x, collide at centre (shockwave ring + radial-gradient flash), burst, overlay fades,
then the report content enters. Lives in `assets/report-template.html`:
- CSS block between `/* ═══ BOOT SEQUENCE OVERLAY · three.js 多空对撞 ═══ */` and `/* ═══ RESPONSIVE · TABLET ═══ */`
- HTML between `<!-- ─── BOOT OVERLAY · three.js 多空对撞 ─── -->` and `<div class="container"`
- JS: the single `<script>` block (boot IIFE + content IIFE)

### Design: the boot owns the timeline, content follows
- `--boot-clear` CSS var = "ms from page start when content entrance begins".
  Boot writes the nominal `1900ms` up-front, then **rewrites it to the real elapsed time** at dismissal
  and dispatches a `uzi:boot-clear` CustomEvent (+ sets `window.__uziBootCleared`).
- The content IIFE no longer reads `--boot-clear` to schedule; it **waits for that signal**
  (fallback timer 8s). Before the signal it freezes `.seat`/`.fighter`/`.punchline` with
  `style.animation = 'none'` so they don't play behind the overlay, then restores + staggers on `start()`.
- Reason: three.js is 670KB from unpkg — a cold fetch takes 1.5–2.4s. With a fixed 1.9s timeline the
  content animation played entirely behind the overlay and was never seen (the "没变啊" class of bug).

### Timeout budgets (two, not one)
- `netTimer` 7s armed at script start — covers the CDN fetch only.
- `sceneTimer` 4s armed in `s.onload` for WebGL init/shader compile, then **re-armed inside `runScene()`
  right after `const t0`** to `(T_END + 1.5)s` for the animation itself. A single budget measured from
  script start gets eaten by CDN + init and truncates the animation (observed: `[boot] scene timeout`).

### three.js traps
- **`points.frustumCulled = false` is mandatory.** Mutating `geometry.attributes.position` each frame
  does NOT refresh the cached `boundingSphere`; at frame 1 the clouds sit at x≈±15, so the stale sphere
  falls outside the frustum and the whole `Points` object disappears once it moves to centre.
- `PointsMaterial` renders **squares** by default. Fixed with a 64px radial-gradient `CanvasTexture`
  used as `map` (+ `AdditiveBlending`) → soft round glowing dots.
- Wrap `new THREE.WebGLRenderer(...)` in try/catch — throws when there's no WebGL context.
- r160 UMD (`three.min.js`) is deprecated but works; loaded dynamically with `onload`/`onerror` + bail.

### Verifying animation in headless (hard-won)
- `page.screenshot()` costs ~1.2s each under swiftshader → only ~3 frames fit in the boot. Use
  **CDP `Page.startScreencast`** instead (non-blocking, ~100+ frames).
- Sample on the **page clock**: `page.waitForFunction(t => performance.now() >= t, {polling:'raf'}, t)`.
  Puppeteer's own `performance.now()` reading after `goto` is NOT page-start.
- **`setInterval` in a headless page is throttled to ~1s** — polling for a flag with a 5ms interval
  reported THREE as loaded 2.4s late. Don't trust interval-based instrumentation; wrap `setTimeout`
  / `console.warn` in `evaluateOnNewDocument` and read the recorded timeline.
- Detect particles numerically, not by eye: count pixels with `g-r>22 && g-b>22` (green) and
  `r-g>22 && r-b>22` (red); a full-screen flash shows up as `max(rgb)>150` jumping ~10x.

## Making the template previewable standalone (模版页面优化)

`assets/report-template.html` is the *input* to the generator: opening it directly showed 94 raw
`{{PLACEHOLDER}}` literals, an empty debate section and 0 of 66 jury seats. Added a
**self-disabling preview layer** so the file renders as a complete page for styling work.

- Source of truth: **`tools/template_preview_layer.js`** (kept out of the HTML so it stays editable).
- **`tools/apply_template_preview.py`** splices it in, idempotently, right after `<script>`
  (markers `TEMPLATE PREVIEW LAYER` / `/TEMPLATE PREVIEW LAYER`). Also normalises the newline run
  after the layer to exactly one blank line, so strip/apply round-trips don't grow the file.
- **`tools/verify_template_preview.mjs`** renders it headless and asserts: 0 raw tokens, 0 broken
  images, 66 seats / 22 dim cards / 3 debate rounds / 9 school cards, and the stance histogram
  is 31 看多 / 13 中性 / 22 看空. `--file <report.html>` reuses it on a real report.
- **`tools/shoot_template_sections.mjs`** captures high-DPI crops of 9 regions for review.

### Hard-won gotchas

- **The token regex needs a capture group around the *inner* name only:**
  `new RegExp(LB + '([A-Z_0-9]+)' + RB, 'g')`. Wrapping the braces too (`'(' + LB + ... + RB + ')'`)
  makes the callback's 2nd arg `"{{NAME}}"` instead of `"NAME"`, so every lookup misses and all 94
  placeholders survive. Omitting the group entirely passes the *offset* instead. Both bugs look
  identical from the outside (nothing substituted) — check the regex first.
- **Substitution happens after parse**, so `<img src="avatars/{{BULL_ID}}.svg">` is fetched *before*
  the script rewrites it → 2 transient `ERR_FILE_NOT_FOUND` console warnings in preview mode only.
  Final DOM is clean (`brokenImgs === 0`). Don't chase these.
- **A literal `<script>` inside the inline script's own comment** (e.g. writing "内联 `<script>`")
  doesn't break the browser (only `</script` ends script data) but does break naive tag-counting
  tooling and my own balance assertion. Reworded to avoid it.
- **Preview markup must match the real injected markup exactly**, or the template's CSS never gets
  exercised. My first draft invented `.msg-head` / `.msg-score` / `.msg-text`; the real contract is
  `.msg-meta` / `.msg-group-tag` / `.msg-signal-dot` / `.msg-score-badge` / `.msg-confidence` /
  `.msg-bubble` / `.msg-reasoning` / `.msg-comment` / `.msg-verdict` / `details.msg-details`.
  Real fragments are extractable with `tools/dump_inject_slots.py` → `/tmp/inject/*.html`.
- **Demo data must be internally consistent.** The page quotes "31 看多 · 13 中性 · 22 看空 · 共识 57%"
  in five places, so the 66 scores are now an explicit `SCORE_STR` table chosen so the per-school
  buckets sum to exactly those numbers (A 5/1/0 · B 6/2/1 · C 2/2/3 · D 0/1/3 · E 6/1/0 · F 6/4/14 ·
  G 2/1/1 · H 3/1/0 · I 1/0/0). Seats and chat read the same map, so a person's score agrees
  everywhere. Top-3 bull/bear cards are sorted from the map, not hand-written.
- `sync_boot_intro.py` now **strips** the preview layer (`strip_preview_layer`) before writing the
  template's `<script>` into reports — otherwise every report carries ~27KB of dead preview code.
  The strip removes the newline *before* the marker too, so it's an exact inverse of `apply_`.

### Known styling defect this surfaced — FIXED

`.msg-reasoning` emits `\n`-separated ✅/❌ bullet lists but the CSS had **no `white-space` rule**,
so they collapsed into one run-on line. Confirmed identical in real reports (not a preview artefact).

Fixed by adding `white-space: pre-wrap` to `.chat-msg .msg-reasoning` — verified rendering as
**6 lines instead of 1**, on both the template and a real report. The verifier now asserts this
(`reasoningInfo`: `whiteSpace === 'pre-wrap' && lines >= 4`) so it can't silently regress.

**Important gap this exposed:** `sync_boot_intro.py` only syncs three blocks — boot CSS, boot HTML,
and the `<script>`. Every *other* template CSS change therefore never reaches reports generated from
an older template revision, and template/reports drift apart silently. Added
**`tools/patch_report_css.py`** with an explicit `(label, sentinel, old, new)` list of surgical CSS
fixes; it's idempotent and refuses to guess (missing anchor → `!!` + non-zero exit). Use it for any
non-boot CSS change that must reach existing reports, then `rebuild_standalone.py`.

## Verifying against the REAL generator (don't trust the template in isolation)

Ran `./uzi BTC-USD --stage2 --no-browser` for the first time all session (BTC-USD has an
`agent_analysis.json`, so it runs offline). Three findings that only a real run could surface:

1. **`uzi` does a BLIND global text substitution over the whole file — including JS comments.**
   My preview layer's comment contained a literal `NAME` placeholder as an example; every generated
   report had it replaced with the stock name (`拿到的是 "{{NAME}}"` → `拿到的是 "Bitcoin"`).
   That single substitution also explained a mysterious 1-byte size delta. **Never write a literal
   paired-brace token anywhere in the template — not even in a comment.** `apply_template_preview.py`
   now hard-fails on a stray token in the layer.
2. **`uzi` does NOT strip `data-page-node-id`** — the fresh report carried 386 of them. My
   `sync_boot_intro.py` strips them, so reports produced by my tooling differ from reports produced
   by `uzi`. (Earlier notes claiming the generator strips them were wrong.)
3. **`uzi` ships the template's preview layer into every report** — measured **26,968 bytes = 7.1%**
   of the HTML. It self-disables at runtime, but `uzi --remote` publishes reports over a public
   tunnel, so it's dead weight in a published artifact.

Fix: added **`tools/gen_report.sh <TICKER>`** — runs `uzi --stage2 --no-browser`, then
`sync_boot_intro.py` + `patch_report_css.py` + `rebuild_standalone.py`. All three are idempotent, so
re-running is safe. Verified end-to-end: the wrapper's output has `layer=0`, `pre-wrap` present,
`node-id=0`, and renders clean (0 raw tokens, 0 broken images, 66 seats, boot overlay dismissed).

**Rule going forward:** after changing the template, generate through `tools/gen_report.sh`, not
bare `uzi` — otherwise the preview layer and stale CSS land in the report.

## Migration: preview layer inlined → external script reference

The 7.1%-dead-weight problem above had one clean fix: **stop inlining the layer into the template**.
`assets/report-template.html` now ends with

```html
<script src="../tools/template_preview_layer.js"></script>
<script> ...boot IIFE + content IIFE... </script>
```

`tools/template_preview_layer.js` (34.6KB) is the single source of truth. Opening the template in a
browser still gives the full preview (relative `<script src>` resolves under `file://`), the template
drops 193KB → 158KB, and a report only inherits a *tag* that `sync_boot_intro.py` strips.

**A better variant than "inline it and strip it":** strip the *reference tag*, not 27KB of code. The
report never contains the layer at all, so there is nothing to keep in sync.

Tooling changes:
- `sync_boot_intro.py` — `extract_script()` now takes the inline block via `tpl.rindex("</script>")`
  (`</script>` occurs **twice** once the src tag exists); new `strip_preview_layer()` handles both the
  src tag **and** the legacy inline form (`PREVIEW_INLINE_BEGIN/END`) so pre-refactor reports
  normalise in one pass; new step 0.5 in `patch()` reports `preview layer stripped`.
- `apply_template_preview.py` **retired** — it inlined the layer, which would have silently undone the
  migration. Replaced by **`tools/lint_preview_layer.py`**, a static guard that checks (1) no literal
  paired-brace token anywhere in the layer, (2) exactly one `<script src=...>` + one inline `<script>`,
  src first, (3) **every template token has a key in the layer's `D` map** (58/58 today). `gen_report.sh`
  runs it before generating.
- `gen_report.sh` — lint step added; header comment updated (the cost is now a tag + 404, not 27KB).

**Trap found while writing the lint:** parsing the `D` map with a line-anchored key regex
(`^\s*([A-Z_0-9]+)\s*:`) saw only **29 of 58** keys, because several share a line. Anchor on
`[{,]\s*([A-Z_0-9]+)\s*:` instead. It reported "29 tokens have no demo value" — a *false alarm* that
looked exactly like a real coverage gap.

**Determinism proof:** regenerated BTC-USD end-to-end (`uzi` → sync → patch → rebuild). Before
normalisation the fresh report had `layer=1`, `node-id=386`. After: `layer=0`, `node-id=0`,
`pre-wrap=3`, and **exactly 375,926 bytes — byte-identical to the previous normalised report**. All 6
reports now read `layer=0 node-id=0 pre-wrap=3 inline=0`; all 6 standalones rebuilt with `missing=0`.

**Console 404s are expected on the template, not the report.** The template preview logs
`ERR_FILE_NOT_FOUND` ×2. Root cause, confirmed by grep: the two distinct placeholder `src` values
`avatars/{{BULL_ID}}.svg` and `avatars/{{BEAR_ID}}.svg` are fetched during parse, *before* the layer
rewrites them. A real report logs **0** warnings (layer absent → no self-disable path). So: count the
distinct placeholder URLs and compare to the warning count — don't hand-wave "probably benign".

## Ran `uzi` on BTC-USD — three real generator defects found

Regenerated via `tools/gen_report.sh BTC-USD` (byte-identical to the previous run again: 375,926B).
Then audited the *content*, not just the render. The template and my tooling are fine; all three
defects are in `uzi`'s synthesis/inject layer (`crates/**/*.rs`, off-limits per the hard gate — so
record the symptom, not the cause).

1. **IC memo's "三情景回报分析" grid is emitted empty.** The report contains
   `<div style="display:grid;grid-template-columns:1fr 1fr 1fr;gap:12px"></div>` — header, no cells.
   The data *does* exist (`synthesis.json → friendly.scenarios.cases`, 5 populated cases) and renders
   correctly in the friendly-trio card. So it is one unfilled slot, not missing data. Fix by filling
   that slot from the same source the friendly card reads.
2. **Risk items render a dangling `()` and a blank description.** e.g.
   `<strong>流动性风险</strong> <span ...>()</span><br><span ...></span>` — the severity/category and
   description fields are empty. Visible in the IC memo's 核心风险+缓解 block.
3. **Exit triggers are equity boilerplate, not asset-class aware.** `agent_analysis.json` carries
   `asset_class: "crypto"`, yet the report emits "下季度营收同比转负", "下次业绩预告低于 +10%",
   "龙虎榜游资席位出现大额净卖出", "PE 站上 5 年 90 分位". Only the 60-day-MA trigger applies to BTC.

but it is why the coverage warning is permanent for non-equity assets.
