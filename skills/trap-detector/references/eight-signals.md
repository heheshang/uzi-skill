# 杀猪盘 8 信号 · 详细判定标准

> 本仓库实现：`crates/uzi-data/src/fetch/trap_signals.rs`（上游同名抓取器的移植，产出维度 `18_trap`）。
> 8 个信号定义在模块内联的 `SIGNALS` 常量中。每个信号实际只执行其 `queries` 数组的**第一条**
> query（`queries.iter().take(1)`），调 `uzi_data::web_search` 取回最多 3 条结果，
> 把有效结果的 `body` 拼成一段文本，再与 `positive_kws` 做**子串包含**匹配。
> `{name}` 为股票名：入参是代码时先经基础信息抓取（`uzi_data::sources`）解析出名称。

**全局命中判定**：
- 同一信号命中 **≥ 2 个** `positive_kws` → 该信号才计入命中（`hits.len() >= 2`）
- 命中 **≥ 3 个**关键词 → 该条 `severity: "high"`，否则 `"medium"`
- `signals_hit_detail[].evidence_kws` 最多记录前 3 个命中关键词

## 信号 1: 大量低质量账号同时推荐

- **真实检索 query**: `{name} 强烈推荐 必涨`
- **命中关键词（`positive_kws`）**: `必涨` / `强烈推荐` / `内部` / `稳赚`
- **辅助观察点**（人工复核，非代码判定）：内容来自 0-100 粉的小号 / 新建公众号；推荐时间集中在近 7-30 天
- **证据收集**: 列出 3-5 个示例 URL 及账号 metric

## 用户输入关键词加权

用户话术本身是证据。本仓库 `trap_signals` **不消费**用户关键词（`trap_score` 只由命中信号数决定），
加权由 agent 在写 `18_trap` 结论时定性应用：

| 用户原话 | 加权 |
|---|---|
| "朋友推荐" / "群里" / "老师" / "带我" | +1 |
| "内幕" / "稳赚" / "稳赚不赔" / "包赚" | +2 |
| "必涨" / "翻倍" | +1 |

命中后应把**结论措辞的警示程度上调 N 档**（落到 `recommendation` 的解读上，不改变 `trap_score` 数值）。

## 评级映射

| 命中信号数 | trap_score | level |
|---|---|---|
| 0-1 | 9 | 🟢 安全 |
| 2-3 | 7 | 🟡 注意 |
| 4-5 | 4 | 🟠 警惕 |
| 6+ | 1 | 🔴 高度可疑 |

> `trap_score` 是**反向分**：越高越安全（1 = 最危险，9 = 最安全）。
